# 레짐 분석용 상태 테이블 (1.3)

이 문서는 상태 테이블을 쓰는 군집화 담당자를 위한 것이다. 테이블을 만들 때
정한 규칙과, 담당자가 직접 골라야 하는 항목을 정리한다. 열별 의미·단위·계산
방법·군집화 사용 여부는 [변수 정의서](state_table_variables.md)에 있다.

## 파일

`outputs/state_table/experiment_1_1/`

| 파일 | 내용 |
| --- | --- |
| `state_table.parquet` | 상태 테이블 (군집화 입력 변수, 제어 결과, 데이터 분할 정보) |
| `normalization.json` | 학습 분할로 계산한 정규화 기준 (변수별 평균·표준편차) |
| `splits.csv` | 시나리오 × 시드별 분할 |
| `build_info.json` | 사용한 실행 수, 제외한 실행, 분할 시드, 구간 길이 |

```python
import pandas as pd

table = pd.read_parquet("outputs/state_table/experiment_1_1/state_table.parquet")
env = table[table["cluster_row"]]                  # 군집화용 (환경 1시점당 1행)
train = env[env["split"] == "train"]
features = [c for c in env.columns
            if c.startswith("env_") and c.endswith("_60m_z")]
```

열 이름 앞부분으로 용도를 구분한다.

| 접두어 | 용도 | 군집화 |
| --- | --- | --- |
| `env_` | 관측 가능한 경매 환경 변수 | 입력 후보 |
| `cfg_` | 시나리오 설정값 (시뮬레이터 정답) | 금지. 군집 해석·검증용 |
| `ctrl_` | 제어 결과 (지출, 지출 오차, 승수, 낙찰 수) | 쓰지 않음. 성능 분석용 |

`cfg_` 열은 실제 운영에서는 알 수 없는 값이다. 군집화 입력에 넣으면 정답을
보고 나누는 것이 되므로, 군집이 설정 조건과 얼마나 맞는지 확인할 때만 쓴다.

## 테이블 단위

한 행은 **캠페인 × 시나리오 × 시드 × PI 계수 × 분**이다.

계획서는 캠페인 × 시나리오 × 시드 × 분 단위를 요구했지만, 같은 시나리오와
시드라도 PI 계수가 다르면 지출·오차·승수가 달라진다. 제어 결과를 한 테이블에
담기 위해 PI 계수를 키에 추가했다.

### 군집화할 때는 `cluster_row == True`인 행만 사용한다

경매 수와 경쟁 입찰 통계 같은 환경 변수는 캠페인과 PI 계수에 관계없이 같은
시나리오·시드·분에서 모두 같다. 그대로 쓰면 같은 환경 관측치가
캠페인 10개 × PI 3개 = 30번 반복된다. `cluster_row`는 시나리오 × 시드 × 분마다
한 행에만 `True`로 표시되어 있다.

```python
env = table[table["cluster_row"]]
```

## 담당자가 정할 항목

### 1. 최근 구간 길이: 15분 또는 60분

환경 변수는 최근 15분과 최근 60분 두 가지로 모두 계산해 두었다. 열 이름 끝의
`_15m`, `_60m`이 구간 길이다.

| 구간 | 장점 | 단점 |
| --- | --- | --- |
| 15분 | 환경 변화를 빨리 반영한다 | 우연한 출렁임에도 값이 흔들린다 |
| 60분 | 값이 안정적이다 | 변화를 늦게 반영한다 |

한쪽만 쓰거나 둘 다 넣고 비교할 수 있다.

### 2. 하루 초반 행: 그대로 쓰기, 빈 값 처리, 또는 삭제

각 실행은 0분부터 시작하는 하루이며, 0분 이전 데이터는 없다. 그래서 하루
초반에는 최근 구간이 덜 차 있다. 예를 들어 10분 시점의 "최근 60분 평균"은
실제로 10분치 평균이다.

테이블은 **덜 찬 구간도 있는 데이터만으로 계산해서 채우고**, 구간이 다 찼는지를
따로 표시한다.

| 열 | 의미 |
| --- | --- |
| `window_filled_15m` | 최근 15분이 다 찼으면 `True` (15분 시점부터) |
| `window_filled_60m` | 최근 60분이 다 찼으면 `True` (60분 시점부터) |

행을 버리지 않았기 때문에 담당자가 원하는 방식으로 바꿀 수 있다.

```python
# 그대로 쓰기: 아무것도 하지 않는다

# 빈 값으로 바꾸기 (원값과 _z 열 모두)
cols_60m = [c for c in table.columns
            if c.startswith("env_") and "_60m" in c]
table.loc[~table["window_filled_60m"], cols_60m] = float("nan")

# 행 삭제
table = table[table["window_filled_60m"]]
```

### 3. 시각 변수 `minute_of_day` 사용 여부

하루 중 몇 번째 분인지(0~1439)를 나타내는 열이다. 군집화 사용 여부는
**선택**이다.

모든 시나리오가 자정에 가장 적고 정오에 가장 많은 트래픽 패턴을 쓴다. 이 열을
넣으면 군집이 경매 환경이 아니라 시간대(낮/밤)로 나뉠 수 있다. 넣는 경우에는
넣지 않은 결과와 비교해 군집이 시간대만 반영하는지 확인한다.

## 고정한 규칙

| 항목 | 규칙 |
| --- | --- |
| 정보 시점 | 모든 변수는 그 분까지 관측된 정보로만 계산한다. 이후 시점 값은 쓰지 않는다. |
| 변수 구분 | 군집화 입력(환경 변수)과 제어 결과(지출, 지출 오차, 승수, 낙찰 수)를 열 이름과 정의서에서 구분한다. 제어 결과는 군집화에 쓰지 않는다. |
| 데이터 분할 | 시드 단위로 나눈다. 학습 42~45, 검증 46. 평가용 데이터는 이 데이터셋에 넣지 않았다. 평가에는 47 이후 시드를 쓰고, 필요할 때 아래 "평가 데이터 생성" 방법으로 만든다. |
| 분할 일관성 | 같은 시나리오·시드의 실행은 PI 계수가 달라도 같은 분할에 넣는다. |
| 정규화 | 기준(평균, 표준편차)은 학습 분할의 `cluster_row` 행으로만 계산하고 검증·평가에도 같은 기준을 적용한다. |

환경 변수는 같은 시나리오·시드의 모든 PI 실행에서 같아야 한다. 생성 코드는
이를 실행마다 비교하고, 다르면 오류로 멈춘다.

## 다시 만들기

```bash
cd regime-aware-budget-pacing
.venv/bin/python -m pip install -r requirements.txt

# 1. 원본 로그 생성 (이미 trace.csv가 있는 실행은 건너뛴다)
.venv/bin/python src/simulator/run_experiments.py \
  --config configs/experiment_1_1.json

# 2. 상태 테이블 생성
.venv/bin/python src/preprocessing/build_state_table.py
```

| 하고 싶은 것 | 방법 |
| --- | --- |
| 데이터 추가 생성 | 설정 파일의 `seeds`, `pi_coefficients`, `scenarios`에 값을 추가하고 1을 다시 실행한다. 새 조합만 실행된다. 그다음 2를 다시 실행한다. |
| 같은 환경에서 다른 PI 계수 평가 | 같은 시나리오·시드로 `pi_coefficients`만 바꿔 실행한다. 경매 수와 경쟁 입찰은 시드로 고정되어 똑같이 재현된다. |
| 평가 데이터 생성 | 설정 파일 `seeds`에 47 이후 시드를 추가하고 1을 실행한 뒤, 2를 `--test-seeds 47`처럼 평가 시드를 지정해 실행한다. 시드 하나당 36개 실행, 약 1시간 15분 걸린다. 학습·검증 데이터와 정규화 기준은 바뀌지 않는다. |
| 분할 시드 변경 | `--train-seeds 42 43 44 45 --validation-seeds 46 --test-seeds 47 48`. 어느 분할에도 없는 시드가 데이터에 있으면 오류로 멈춘다. |
| 변수 정의서 갱신 | `src/preprocessing/state_table.py`의 `COLUMNS`를 고친 뒤 `--write-docs`로 다시 생성한다. |

180개 실행 기준으로 1은 약 6시간 30분, 2는 약 20초 걸린다.
