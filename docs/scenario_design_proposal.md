# 실험 시나리오 설계 제안

이 문서는 시나리오 구성을 팀에서 검토하기 위한 제안서다. 현재
`configs/experiment_1_1.json`에는 12개가 구현되어 있으며, 아래 표에서는
HDBSCAN 레짐 기준점과 역방향 전환을 위해 3개를 추가한 15개 구성을 제안한다.

## 공통 조건

| 항목 | 현재 제안값 | 비고 |
| --- | ---: | --- |
| 실행 시간 | 1,440분 | 하루 |
| 조건 변경 시점 | 720분 | 정오 |
| 캠페인 수 | 10개 | 계산량을 줄인 파일럿 값 |
| 캠페인별 일 예산 | 100 | 모든 캠페인에 동일 적용 |
| 트래픽 phase | 0.5 | 자정 최저, 정오 최고 |
| 시드 | 42, 43 | 최종 통계 분석에는 추가 시드 검토 필요 |
| PI 조합 | `(0.1, 0.001)`, `(0.5, 0.01)` | 현재는 예시 후보이며 최종 확정 필요 |

## 환경 수준

| 변수 | 낮음 | 기준 | 높음 |
| --- | ---: | ---: | ---: |
| 트래픽 `dc` | 1,500 | 3,000 | 4,500 |
| 트래픽 `amplitude` | 0.2 | 0.6 | 0.9 |
| 경쟁 입찰 수 계수 | 0.5 | 2.0 | 4.0 |
| 경쟁 가격 배율 | 0.5 | 1.0 | 2.0 |

아래 표의 환경 표기는 `dc / amplitude / 경쟁 입찰 수 계수 / 경쟁 가격 배율`
순서다.

## 이 구성을 권장하는 이유

1. `baseline_static`을 기준으로 한 번에 한 변수만 바꾸는 8개 시나리오가 각
   변수의 영향을 분리한다.
2. `combined_low_static`, `combined_high_static`이 HDBSCAN에 명확한 저강도·고강도
   레짐 기준점을 제공한다.
3. 전환 시나리오가 같은 하루 안에서 레짐 변화와 PI 제어기의 반응을 관찰하게
   한다.
4. 고→저 역방향 전환을 포함해야 전환 방향에 따른 비대칭과 히스테리시스를
   확인할 수 있다.

## 팀에서 확정해야 할 항목

| 결정 항목 | 현재 값 | 논의할 점 |
| --- | --- | --- |
| 캠페인 수 | 10 | Yahoo 기본값 100보다 작다. 계산량과 대표성 사이 선택 필요 |
| 일 예산 | 100 고정 | 고정 예산을 유지할지 Yahoo 분포를 사용할지 결정 필요 |
| 시드 수 | 2개 | 통계적 안정성을 위해 5개 이상으로 늘릴지 검토 필요 |
| PI 조합 | 2개 | 현재 값은 예시다. 탐색 범위나 후보 목록 확정 필요 |
| 전환 시점 | 정오 | 정오의 자연 트래픽 피크와 전환 효과가 겹치는 문제 검토 필요 |
| 전환 방향 | 저→고 중심 | 고→저 시나리오를 어디까지 추가할지 결정 필요 |

## 권장 실행 순서

1. `baseline_static`, `combined_low_static`, `combined_high_static`,
   `combined_low_to_high_at_noon`, `combined_high_to_low_at_noon`의 5개로 파일럿을
   먼저 실행한다.
2. 출력 열과 실행 시간을 확인한 뒤 전체 15개 시나리오로 확장한다.
3. 시드 수와 PI 계수 목록은 파일럿 결과를 확인한 후 확정한다.
4. 81개 전체 조합은 대표 시나리오에서 레짐 분리가 부족할 때만 추가한다.
