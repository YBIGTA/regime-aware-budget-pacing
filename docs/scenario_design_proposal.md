# 실험 시나리오 설계

환경 표기는 `dc / amplitude / 경쟁 입찰 수 계수 / 경쟁 가격 배율` 순서다.

## 공통 조건

| 항목             | 값                                             | 비고                                   |
| ---------------- | ---------------------------------------------- | -------------------------------------- |
| 실행 시간        | 1,440분                                        | 하루                                   |
| 캠페인 수        | 10개                                           | Yahoo 기본값 100보다 작음. 계산량 고려 |
| 캠페인별 일 예산 | 1,000                                          | 보정 결과로 확정 (아래 참고)           |
| 트래픽 phase     | 0.5                                            | 자정 최저, 정오 최고                   |
| 기준 환경        | `3000 / 0.6 / 2 / 1`                           |                                        |
| PI 계수          | 약 `(1, 0.01)`, 중 `(5, 0.05)`, 강 `(50, 0.5)` | 보정 결과로 확정 (아래 참고)           |

## 환경 수준

| 변수               |  낮음 |  기준 |  높음 |
| ------------------ | ----: | ----: | ----: |
| 트래픽 `dc`        | 1,500 | 3,000 | 4,500 |
| 트래픽 `amplitude` |   0.2 |   0.6 |   0.9 |
| 경쟁 입찰 수 계수  |   0.5 |     2 |     4 |
| 경쟁 가격 배율     |   0.5 |     1 |     2 |

## 시나리오

전체 시나리오는 고정 81개와 정오 전환 4개를 합친 85개다. 기본 시나리오 15개는
이 중에서 대표로 고른 것이다.

| 그룹 | 만드는 방법                                             | 개수 | 그중 기본 시나리오 | ID 규칙                                                                                |
| ---- | ------------------------------------------------------- | ---: | ------------------ | -------------------------------------------------------------------------------------- |
| 고정 | 환경 수준 4변수 × 3수준 전체 조합. 하루 동안 조건 유지 |   81 | 1~11               | 기본은 아래 표의 ID, 나머지 70개는 `grid_dc{dc}_amp{amplitude}_cnt{계수}_px{배율}` |
| 전환 | 정오(720분)에 조건이 바뀜                               |    4 | 12~15              | 아래 표의 ID                                                                           |

### 고정 그룹 81개

환경 수준 표의 4변수를 각각 낮음·기준·높음 중 하나로 골라 하루 동안 유지한다.
81개 모두 3 × 3 × 3 × 3 조합이다. 아래 표는 기준 환경에서 몇 개 변수를 바꿨는지로 나눈 것이다.

| 기준에서 바꾼 변수 | 개수 | 만드는 방법                         | 예시                   | 기본에 포함                      |
| ------------------ | ---: | ----------------------------------- | ---------------------- | -------------------------------- |
| 0개                |    1 | 모두 기준                           | `3000 / 0.6 / 2 / 1`   | #1                               |
| 1개                |    8 | 4변수 중 1개 × 낮음·높음            | `4500 / 0.6 / 2 / 1`   | #2~#9 (전부)                     |
| 2개                |   24 | 4변수 중 2개 × 낮음·높음 조합 4가지 | `4500 / 0.6 / 2 / 2`   | 없음                             |
| 3개                |   32 | 4변수 중 3개 × 낮음·높음 조합 8가지 | `4500 / 0.9 / 4 / 1`   | 없음                             |
| 4개                |   16 | 4변수 모두 × 낮음·높음 조합 16가지  | `1500 / 0.9 / 0.5 / 2` | #10 (전부 낮음), #11 (전부 높음) |
| 합계               |   81 |                                     |                        | 11개                             |

변수 1개만 바꾼 시나리오만으로는 HDBSCAN이 실제 레짐 대신 실험 설계점을 군집으로
찾을 수 있다. 2~4개를 함께 바꾼 70개가 이를 보완한다.

## 수집 데이터

run 수는 `시나리오 수 * 시드 수 * PI 수`다.

| 실험 ID                   | 시나리오               | 시드  | run 수                      | 용도                  |
| ------------------------- | ---------------------- | ----- | --------------------------- | --------------------- |
| `experiment_1_1`          | 기본 1~9, 12~15 (13개) | 42~46 | 13 * 5(시드) * 3(PI) = 195  | 군집화 학습·검증      |
| `experiment_2_test_seeds` | 기본 15개              | 47~61 | 15 * 15(시드) * 3(PI) = 675 | 상태 테이블 평가 분할 |
| `experiment_3_static`     | 고정 그룹 81개         | 42~46 | 81 * 5(시드) * 3(PI) = 1,215 | 레짐 분리 보강        |

- 합계는 2,085 run이다. `experiment_3_static`의 135 run(기본 1~9 × 시드 5 × PI 3)은
  `experiment_1_1`과 같은 실행이라, 상태 테이블에는 중복 없이 1,950 run이 들어간다.
- 학습·검증(42~46)에는 시나리오 85개 전체가, 평가(47~61)에는 기본 15개가 들어간다.
- 상태 테이블은 `outputs/state_table/experiments_1_to_3/`에 있고, 세 실험을 합쳐 만든다.
- `experiment_2`·`3` 설정 파일은 `experiments/data_collection/make_configs.py`로 만든다. `experiment_1_1`은 직접 작성했다.

## 예산·PI 보정 근거 (2026-11-01)

| 항목                    | 결과                                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 예산 100 (폐기)         | 모든 캠페인이 30~40분 만에 예산을 소진했다. 결과는 `_discarded/`에 있다                                                    |
| 예산 1,000              | 페이싱 없이 측정한 하루 지출 여력(시나리오별 중앙값 약 2,000~6,000)보다 작다. 모든 시나리오에서 페이싱이 필요하다          |
| PI 약·중·강             | 후보 8개 중 Kp가 약 10배씩 다르고 Ki/Kp = 0.01인 세 조합을 골랐다. TE는 약 ≈ 0.10, 중 ≈ 0.014~0.026, 강 ≈ 0.001~0.011이다 |
| 사용하지 않은 기존 기록 | Yahoo 원본 `No_Pacing.csv`(하루 요약만 있음), `trace_example.csv`(10분짜리 예시)                                           |

보정 스크립트는 `experiments/calibration/calibrate.py`, 결과는 `outputs/calibration/`에 있다.
