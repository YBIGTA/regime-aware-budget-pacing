# 실험 시나리오 설계

환경 표기는 `dc / amplitude / 경쟁 입찰 수 계수 / 경쟁 가격 배율` 순서다.

## 공통 조건

| 항목             | 값                     | 비고                                   |
| ---------------- | ---------------------- | -------------------------------------- |
| 실행 시간        | 1,440분                | 하루                                   |
| 캠페인 수        | 10개                   | Yahoo 기본값 100보다 작음. 계산량 고려 |
| 캠페인별 일 예산 | 1,000                  | 보정 결과로 확정 (아래 참고)           |
| 트래픽 phase     | 0.5                    | 자정 최저, 정오 최고                   |
| 기준 환경        | `3000 / 0.6 / 2 / 1` |                                        |

| 변수                 |  낮음 |  기준 |  높음 |

| 경쟁 입찰 수 계수    |   0.5 |     2 |     4 |
| 경쟁 가격 배율       |   0.5 |     1 |     2 |

## 시나리오

전체 시나리오는 아래 세 그룹을 합친 107개다. **기본 시나리오 15개는 별도
시나리오가 아니라, 이 107개 중에서 대표로 고른 부분집합이다.** 실행 횟수가 많은
실험(평가 시드, PI 그리드)은 기본 15개로만 돌린다.

| 그룹 | 만드는 방법                                             | 개수 | 그중 기본 시나리오    | ID 규칙                                                                              |
| ---- | ------------------------------------------------------- | ---: | --------------------- | ------------------------------------------------------------------------------------ |
| 고정 | 환경 수준 4변수 × 3수준 전체 조합. 하루 동안 조건 유지 |   81 | 1~11                  | 기본은 아래 표의 ID, 나머지 70개는 `grid_dc{dc}_amp{amplitude}_cnt{계수}_px{배율}` |
| 전환 | 아래 전환 3종류 × 방향 2개 × 시점 3개                 |   18 | 12~15 (정오 전환 4개) | `{traffic\|competition\|combined}_{low_to_high\|high_to_low}_at_{0600\|noon\|1800}`     |
| 충격 | 기준 환경에서 60분 동안 한 변수를 바꿨다가 복귀         |    8 | 없음                  | `shock_{종류}_at_{0500\|1500}`                                                      |

### 고정 그룹 81개

환경 수준 표의 4변수를 각각 낮음·기준·높음 중 하나로 골라 하루 동안 유지한다.
81개 모두 3 × 3 × 3 × 3 조합이다. 아래 표는 기준 환경에서 몇 개 변수를 바꿨는지로 나눈 것이다.

| 기준에서 바꾼 변수 | 개수 | 만드는 방법                           | 예시                     | 기본에 포함                      |
| ------------------ | ---: | ------------------------------------- | ------------------------ | -------------------------------- |
| 0개                |    1 | 모두 기준                             | `3000 / 0.6 / 2 / 1`   | #1                               |
| 1개                |    8 | 4변수 중 1개 × 낮음·높음            | `4500 / 0.6 / 2 / 1`   | #2~#9 (전부)                     |
| 2개                |   24 | 4변수 중 2개 × 낮음·높음 조합 4가지 | `4500 / 0.6 / 2 / 2`   | 없음                             |
| 3개                |   32 | 4변수 중 3개 × 낮음·높음 조합 8가지 | `4500 / 0.9 / 4 / 1`   | 없음                             |
| 4개                |   16 | 4변수 모두 × 낮음·높음 조합 16가지  | `1500 / 0.9 / 0.5 / 2` | #10 (전부 낮음), #11 (전부 높음) |
| 합계               |   81 |                                       |                          | 11개                             |

지금 데이터에는 변수 1개만 바꾼 시나리오가 대부분이다. 2~4개를 함께 바꾼 70개를
추가해야 HDBSCAN이 실험 설계점이 아닌 실제 레짐을 구분할 수 있다.

### 전환 그룹 18개

| 전환 종류   | 낮음 조건                  | 높음 조건              | 방향           | 전환 시점         | 기본에 포함                        |
| ----------- | -------------------------- | ---------------------- | -------------- | ----------------- | ---------------------------------- |
| traffic     | `1500 / 0.6 / 2 / 1`     | `4500 / 0.6 / 2 / 1` | 저→고, 고→저 | 360·720·1,080분 | 저→고 정오 (12)                   |
| competition | `3000 / 0.6 / 0.5 / 0.5` | `3000 / 0.6 / 4 / 2` | 저→고, 고→저 | 360·720·1,080분 | 저→고 정오 (13)                   |
| combined    | `1500 / 0.2 / 0.5 / 0.5` | `4500 / 0.9 / 4 / 2` | 저→고, 고→저 | 360·720·1,080분 | 저→고 정오 (14), 고→저 정오 (15) |

정오는 일중 트래픽 피크와 겹친다. 그래서 6시·18시 전환을 함께 넣어 둘을 구분한다.

방향2개 * 전환시점3개 * (낮음/높음)조건 종류 3개 = 18개

### 충격 그룹 8개

| 충격             | 기준 환경에서 바꾸는 값  | 시점       | 지속         |
| ---------------- | ------------------------ | ---------- | ------------ |
| `traffic_up`   | `dc` 3,000 → 9,000    | 300·900분 | 60분 후 복귀 |
| `traffic_down` | `dc` 3,000 → 900      | 300·900분 | 60분 후 복귀 |
| `price_up`     | 경쟁 가격 배율 1 → 3    | 300·900분 | 60분 후 복귀 |
| `count_up`     | 경쟁 입찰 수 계수 2 → 8 | 300·900분 | 60분 후 복귀 |

충격값은 일부러 환경 수준 범위 밖으로 잡았다. 학습에 없던 상황을 만들어 HDBSCAN 노이즈 대응(H4)을 보기 위해서다.

## 실행 계획

run 수는 `시나리오 수 * 시드 수 * PI 수`다. 실험마다 그룹 전체를 실행하므로
`experiment_1_1`에서 이미 실행한 조합도 다시 포함된다. 같은 시드면 결과는 같고,
상태 테이블을 만들 때 하나만 쓴다.

| 실험 ID | 시나리오 | PI | 시드 | run 수 | 실행 위치 | 용도 | 상태 |
| --- | --- | --- | --- | ---: | --- | --- | --- |
| `experiment_1_1` | 기본 1~9, 12~14 (12개) | 기본 3 | 42~46 | 12 * 5(시드) * 3(PI) = 180 | 맥 | 군집화 학습·검증 | 완료 |
| `experiment_2_test_seeds` | 기본 15개 | 기본 3 | 47~61 | 15 * 15(시드) * 3(PI) = 675 | GCP VM | 상태 테이블 평가 분할 | 실행 중 (11/02) |
| `experiment_3_static_mac` | 고정 그룹 81개 | 기본 3 | 42~44 | 81 * 3(시드) * 3(PI) = 729 | 맥 | 레짐 분리 보강 | 실행 중 (11/02) |
| `experiment_3_static_vm` | 고정 그룹 81개 | 기본 3 | 45~46 | 81 * 2(시드) * 3(PI) = 486 | GCP VM | 레짐 분리 보강 | `experiment_2` 다음 |
| `experiment_4_pi_grid` | 기본 15개 | 그리드 21 | 42~46 | 15 * 5(시드) * 21(PI) = 1,575 | 미정 | H1 계수 비교 (파트 1과 협의) | 대기 |
| `experiment_5_transitions` | 전환 그룹 18개 | 기본 3 | 42~46 | 18 * 5(시드) * 3(PI) = 270 | 미정 | H3 | 대기 (H3 일정) |
| `experiment_6_shocks` | 충격 그룹 8개 | 기본 3 | 42~46 | 8 * 5(시드) * 3(PI) = 120 | 미정 | H4 | 대기 (H4 일정) |

- `experiment_3_static`은 81개 시나리오 전체 설정이다. 이번 수집에서는 시드로 나눠
  `_mac`(42~44)과 `_vm`(45~46) 두 설정으로 실행한다.
- 상태 테이블(`outputs/state_table/experiments_1_to_3/`)은 `experiment_1_1`, `_2`,
  `_3_static_mac`, `_3_static_vm`을 합쳐 만든다. 실험 4~6은 넣지 않는다.
- 설정 파일은 `experiments/data_collection/make_configs.py`로 다시 만들 수 있다.

### 실행 속도 (실측)

| 환경 | run 하나 | 처리량 |
| --- | ---: | ---: |
| 맥 M1, 순차 실행 | 약 2.2분 | 약 0.45개/분 |
| 맥 M1, `--workers 8` | 약 2.5분 | 약 3개/분 |
| GCP `c2d-highcpu-32` Spot, `--workers 32` | 약 4.5~9.5분 | 약 4개/분 |

- GCP VM은 시간당 약 $0.2~0.3다. 계정 vCPU 할당량이 32개라 이 VM 1대가 상한이다.
- 출력 용량은 run당 약 5.5MB다.
- GCP 실행 방법은 `experiments/data_collection/gcp_vm.sh`의 주석에 있다. 수집이
  끝난 뒤 받기·검증·상태 테이블 생성은
  `experiments/data_collection/finish_collection.sh`가 한 번에 한다.
