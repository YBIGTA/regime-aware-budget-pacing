# 실험 시나리오 설계 제안

이 문서는 시나리오 구성을 팀에서 검토하기 위한 제안서다. 현재
`configs/experiment_1_1.json`에는 12개가 구현되어 있으며, 아래 표에서는
HDBSCAN 레짐 기준점과 역방향 전환을 위해 3개를 추가한 15개 구성을 제안한다.

## 공통 조건

| 항목 | 현재 제안값 | 비고 |
| --- | ---: | --- |
| 실행 시간 | 1,440분 | 하루 |
| 조건 변경 시점 | 720분 | 정오 |
| 캠페인 수 | 10개 | 계산량을 줄인 파일럿 값 |
| 캠페인별 일 예산 | 1,000 | 모든 캠페인에 동일 적용. 보정 실험으로 확정 (아래 참고) |
| 트래픽 phase | 0.5 | 자정 최저, 정오 최고 |
| 시드 | 42~46 | 학습 42~45, 검증 46. 47 이후는 평가용으로 예약 |
| PI 조합 | 약 `(1, 0.01)`, 중 `(5, 0.05)`, 강 `(50, 0.5)` | 보정 실험으로 확정 (아래 참고) |

## 환경 수준

| 변수 | 낮음 | 기준 | 높음 |
| --- | ---: | ---: | ---: |
| 트래픽 `dc` | 1,500 | 3,000 | 4,500 |
| 트래픽 `amplitude` | 0.2 | 0.6 | 0.9 |
| 경쟁 입찰 수 계수 | 0.5 | 2.0 | 4.0 |
| 경쟁 가격 배율 | 0.5 | 1.0 | 2.0 |

아래 표의 환경 표기는 `dc / amplitude / 경쟁 입찰 수 계수 / 경쟁 가격 배율`
순서다.

## 이 구성을 권장하는 이유

1. `baseline_static`을 기준으로 한 번에 한 변수만 바꾸는 8개 시나리오가 각
   변수의 영향을 분리한다.
2. `combined_low_static`, `combined_high_static`이 HDBSCAN에 명확한 저강도·고강도
   레짐 기준점을 제공한다.
3. 전환 시나리오가 같은 하루 안에서 레짐 변화와 PI 제어기의 반응을 관찰하게
   한다.
4. 고→저 역방향 전환을 포함해야 전환 방향에 따른 비대칭과 히스테리시스를
   확인할 수 있다.

## 팀에서 확정해야 할 항목

| 결정 항목 | 현재 값 | 논의할 점 |
| --- | --- | --- |
| 캠페인 수 | 10 | Yahoo 기본값 100보다 작다. 계산량과 대표성 사이 선택 필요 |
| 일 예산 | 1,000 고정 (확정) | 캠페인별 지출 여력이 2~3배 달라 예산 대비 여력 비율이 이미 다양하다 |
| 시드 수 | 5개 (확정) | 평가용 시드는 필요할 때 47번부터 추가 생성 |
| PI 조합 | 3개 (확정) | 반응 강도별 약·중·강. 파트 1에서 새 후보를 넣어 재평가 가능 |
| 전환 시점 | 정오 | 정오의 자연 트래픽 피크와 전환 효과가 겹치는 문제 검토 필요 |
| 전환 방향 | 저→고 중심 | 고→저 시나리오를 어디까지 추가할지 결정 필요 |

## 권장 실행 순서

1. `baseline_static`, `combined_low_static`, `combined_high_static`,
   `combined_low_to_high_at_noon`, `combined_high_to_low_at_noon`의 5개로 파일럿을
   먼저 실행한다.
2. 출력 열과 실행 시간을 확인한 뒤 전체 15개 시나리오로 확장한다.
3. 시드 수와 PI 계수 목록은 파일럿 결과를 확인한 후 확정한다.
4. 81개 전체 조합은 대표 시나리오에서 레짐 분리가 부족할 때만 추가한다.

## 예산·PI 계수 보정 (2026-11-01)

예산 100과 예시 PI 계수 `(0.1, 0.001)`, `(0.5, 0.01)`로 실행하면 모든 캠페인이
하루 예산을 30~40분 만에 소진했다. PI 오차는 예산 대비 비율(최대 1)이라 Kp 0.1로는
승수가 최대 0.1밖에 움직이지 않고, 예산 100은 캠페인의 하루 지출 여력의 2~5%에
불과했기 때문이다. 이 결과는 사용하지 않는다.

보정 스크립트: `experiments/calibration/calibrate.py`, 결과: `outputs/calibration/`

1. 페이싱 없이 캠페인별 하루 지출 여력을 측정했다 (시드 42).

   | 시나리오 | 여력 중앙값 | 범위 |
   | --- | ---: | ---: |
   | traffic_low_static | 약 2,000 | 1,070~2,840 |
   | competition_price_high_static | 약 3,100 | 1,680~4,540 |
   | baseline_static | 약 4,000 | 2,130~5,660 |
   | traffic_high_static | 약 6,000 | 3,210~8,490 |

   예산 1,000은 모든 시나리오에서 여력보다 작아 페이싱이 필요하고, 여력 대비
   비율이 0.12~0.93으로 퍼진다. 예산이 200 이상이면 Yahoo의 높은 예산 구간
   입찰가 분포를 쓴다.

2. 예산 1,000에서 PI 후보 8개를 비교해 Kp가 약 10배씩 다르고 Ki/Kp = 0.01인 세
   조합을 골랐다. 5개 시나리오에서 하루 전에 예산을 다 쓴 캠페인은 없었다.

   | 시나리오 | 약 TE | 중 TE | 강 TE |
   | --- | ---: | ---: | ---: |
   | baseline_static | 0.101 | 0.014 | 0.001 |
   | traffic_high_static | 0.101 | 0.014 | 0.001 |
   | competition_price_high_static | 0.102 | 0.014 | 0.002 |
   | traffic_low_static | 0.099 | 0.026 | 0.011 |
   | combined_low_to_high_at_noon | 0.120 | 0.021 | 0.003 |

   지출 여력이 작은 캠페인은 새벽 저트래픽 구간에 승수를 1로 올려도 선형 목표를
   따라가지 못해, PI 계수와 무관하게 TE가 약 0.05 남는다.
