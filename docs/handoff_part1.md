# 파트 1 전달: 레짐 분석용 데이터셋

1번 담당자가 파트 1(레짐 구분과 레짐별 PI 계수 탐색)에 넘기는 데이터와 코드를 정리한 문서다.

환경 표기는 `dc / amplitude / 경쟁 입찰 수 계수 / 경쟁 가격 배율` 순서다.

### 규모

한 행은 캠페인 × 시나리오 × 시드 × PI × 분이다. 전체 약 2,808만 행이다.

| 분할 | 시드  | 시나리오  | 군집화용 행 (`cluster_row`) |
| ---- | ----- | --------- | --------------------------: |
| 학습 | 42~45 | 85개      |                     489,600 |
| 검증 | 46    | 85개      |                     122,400 |
| 평가 | 47~61 | 기본 15개 |                     324,000 |

### 바로 시작하기

```python
import pandas as pd

table = pd.read_parquet("outputs/v1/state_table/experiments_1_to_3/state_table.parquet")
env = table[table["cluster_row"]]          # 환경 1시점당 1행
train = env[env["split"] == "train"]
features = [c for c in env.columns
            if c.startswith("env_") and c.endswith("_60m_z")]
```

### 열 구분

| 접두어  | 용도                                         | 군집화                  |
| ------- | -------------------------------------------- | ----------------------- |
| `env_`  | 관측 가능한 경매 환경 변수                   | 입력 후보               |
| `cfg_`  | 시나리오 설정값 (시뮬레이터 정답)            | 금지. 군집 해석·검증용 |
| `ctrl_` | 제어 결과 (지출, 지출 오차, 승수, 낙찰 수)   | 쓰지 않음. 성능 분석용 |

### 환경 변수 (`env_`, 군집화 입력 후보)

| 변수                                   | 의미                         | 계산                                                       |
| -------------------------------------- | ---------------------------- | ---------------------------------------------------------- |
| `env_auctions`                         | 해당 분 경매 수              |                                                            |
| `env_comp_bids_per_auction`            | 해당 분 경매 1건당 경쟁 입찰 수 |                                                         |
| `env_comp_price_mean`                  | 해당 분 경쟁 입찰가 평균     |                                                            |
| `env_auctions_mean_{15m,60m}`          | 최근 구간 분당 경매 수 평균  |                                                            |
| `env_auctions_trend_{15m,60m}`         | 최근 구간 경매 수 증감률     | 최소제곱 기울기 × (구간 길이 − 1) / 구간 평균              |
| `env_auctions_cv_{15m,60m}`            | 최근 구간 경매 수 변동성     | 표준편차 / 평균                                            |
| `env_comp_bids_per_auction_{15m,60m}`  | 최근 구간 경매 1건당 경쟁 입찰 수 |                                                       |
| `env_comp_price_mean_{15m,60m}`        | 최근 구간 경쟁 입찰가 평균   |                                                            |
| `env_comp_price_std_{15m,60m}`         | 최근 구간 경쟁 입찰가 표준편차 |                                                          |
| `env_comp_price_max_{15m,60m}`         | 최근 구간 경쟁 입찰가 최댓값 |                                                            |

- 최근 구간은 해당 분을 포함한 과거 15분 또는 60분이다. 이후 시점 값은 쓰지 않았다.
- 각 변수에 `_z`가 붙은 열이 정규화한 값이다.

### 그 밖의 열

| 열                                       | 의미                                                    |
| ---------------------------------------- | ------------------------------------------------------- |
| `scenario_id`, `seed`, `kp`, `ki`, `campaign_id`, `minute` | 행 키                                   |
| `split`                                  | `train` / `validation` / `test`                         |
| `cluster_row`                            | 군집화용 대표 행 (시나리오 × 시드 × 분마다 1행)         |
| `window_filled_15m`, `window_filled_60m` | 최근 구간이 다 찼는지 (15분·60분 시점부터 `True`)       |
| `minute_of_day`                          | 하루 중 시각 (0~1439)                                   |
| `cfg_traffic_dc` 등 `cfg_`               | 설정된 트래픽 규모·변동폭, 경쟁 입찰 수 계수·가격 배율, 조건 시작 분 |
| `ctrl_spend_error_ratio` 등 `ctrl_`      | 목표·실제 누적 지출, 지출 오차, 예산 대비 오차, 분당 지출·낙찰 수, 남은 예산, 입찰 승수, 적분 상태 |

TE(Tracking Error)는 `ctrl_spend_error_ratio`의 절댓값을 하루 평균한 값이다.

### 지켜야 할 것

| 항목        | 규칙                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| 중복 제거   | 군집화에는 `cluster_row == True`인 행만 쓴다                             |
| 정규화      | `_z` 열은 학습 기준으로 이미 정규화돼 있다. 검증·평가에 다시 하지 않는다 |

### 직접 정할 것

| 항목                 | 선택지                   | 참고                                                                                   |
| -------------------- | ------------------------ | -------------------------------------------------------------------------------------- |
| 구간 길이            | 15분, 60분, 둘 다        | 15분은 변화를 빨리 반영하고, 60분은 안정적이다                                        |
| 하루 초반 행         | 그대로, 빈 값, 삭제      | 하루가 0분에 시작해서 초반에는 구간이 덜 찬 채로 계산돼 있다. `window_filled_*`로 구분한다 |
| `minute_of_day` 사용 | 넣기, 빼기               | 모든 시나리오가 자정 최저·정오 최고라, 넣으면 군집이 낮·밤으로만 나뉠 수 있다         |

## PI 그리드

`experiment_4_pi_grid`(기본 15개 × 시드 42~46 × PI 21개)의 제어 결과다. 경매 환경은 PI 계수와
무관해서 환경 변수는 넣지 않았다. 상태 테이블의 군집화용 행과 `scenario_id`, `seed`, `minute`으로
합치면 레짐 라벨을 붙일 수 있다.

| 파일                    | 내용                                                                            |
| ----------------------- | ------------------------------------------------------------------------------- |
| `control_table.parquet` | 캠페인 × 시나리오 × 시드 × PI × 분. 키 열, `ctrl_` 열(상태 테이블과 같음), `split` |
| `run_summary.csv`       | run별 `te`, `budget_spent_ratio`(하루 지출 / 예산), `signal_change_per_minute`(분당 승수 변화 절댓값 평균). 캠페인 10개 평균 |

```python
ctrl = pd.read_parquet("outputs/v1/control_table/experiment_4_pi_grid/control_table.parquet")
labels = env[["scenario_id", "seed", "minute", "regime"]]   # 군집화 결과
te = (ctrl.merge(labels, on=["scenario_id", "seed", "minute"])
          .assign(abs_err=lambda d: d["ctrl_spend_error_ratio"].abs())
          .groupby(["regime", "kp", "ki"])["abs_err"].mean()
          .unstack(["kp", "ki"]))                            # 행 레짐, 열 PI, 값 TE
```

- 학습 시드 기준으로는 15개 시나리오 모두 가장 강한 `(50, 1.5)`의 TE가 가장 낮다. 대신 승수 변화가
  `(5, 0.05)`보다 약 4배 크다. 허용할 승수 변동 수준을 먼저 정하거나 탐색 범위를 더 넓혀야 한다.
- 하루 내내 한 PI로 돌린 결과라, 레짐별 TE에는 앞 레짐에서 쌓인 오차도 섞여 있다.
- 기본 15개에 없는 레짐(고정 그룹 나머지 70개에만 나오는 레짐)은 아래 방법으로 다시 실행해야 한다.
- PI 3개(`(1, 0.01)`, `(5, 0.05)`, `(50, 0.5)`)는 상태 테이블의 같은 run과 값이 같다.

## 새 PI 계수로 다시 실행

설정 파일의 `pi_coefficients`만 바꿔 실행하면 같은 시나리오·시드의 같은 경매 환경에서
PI만 다르게 비교할 수 있다. 예를 들어 `configs/v1/experiment_1_1.json`을 복사해 아래 부분을 바꾼다.

```json
{
  "experiment_id": "my_pi_test",
  "seeds": [42, 43, 44, 45],
  "pi_coefficients": [
    {"kp": 2.0, "ki": 0.02},
    {"kp": 10.0, "ki": 0.1}
  ],
  "scenarios": [ ... ]
}
```

```bash
.venv/bin/python src/simulator/run_experiments.py --config configs/my_pi_test.json --workers 8
```

결과는 `outputs/simulation_runs/<experiment_id>/runs/<run_id>/trace.csv`에 run마다 생긴다.
이미 있는 run은 건너뛰므로, 중간에 멈춰도 다시 실행하면 이어서 한다.
