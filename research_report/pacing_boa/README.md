# BOA로 두 보정 모델의 입찰 승수 결합

기존 G_A05는 하나의 제어기에 민감도 Ki 보정과 비대칭 지출 목표 보정을 함께 적용한다.
이 실험은 G(민감도 보정만)와 CMA_A05(비대칭 보정만)가 같은 실제 상태를 보고
각각 제안하는 승수를 `w_G * action_G + w_A05 * action_A05`로 결합한다.
각 제어기는 자신의 PI 내부 상태를 유지하며, 관측 이력과 잔여 예산은 실제 결합 경로를 공유한다.

BOA는 50:50에서 시작한다. 완료된 5분 경매 구간을 두 후보 승수로 각각 다시 계산하고,
같은 시작 잔액에서의 다음 추종 오차를 비교해 다음 구간의 비중을 갱신한다.
마지막 구간에는 미소진 손실을 추가한다. 가중치는 하루 사이에도 이어지고,
PI 적분과 민감도 추정 상태는 매일 초기화한다. 미래 구간은 갱신에 사용하지 않는다.

BOA Figure 1의 고정 학습률 버전을 사용한다.
`r = loss - dot(weights, loss)`에 대해 `logw -= eta*r + eta**2*r**2`이다.
기본 eta=0.5, 오차 정규화 기준=예산의 1%이다. 손실은
`0.5*min(abs(next_error)/0.01,1) + terminal*0.5*min(unspent/0.01,1)`이다.
승수 변동은 평가지표로만 보고한다. 이 손실은 기존 일별 합산 목적함수와 같지 않다.

자료: https://arxiv.org/html/1404.1356v5 (Figure 1).
이 실험은 BOA 갱신을 피드백 제어에 적용한 방식이다. 경매 지출이 승수의 선형 함수가
아니므로, 예측 결합에서의 BOA 이론 보장을 제어 성능에 그대로 적용하지 않는다.
갱신은 미실행 후보의 해당 구간 지출도 계산할 수 있는 합성 시뮬레이터를 전제로 한다.

기존 확인 자료 560000~560999만 사용한다. 새 BOA의 개발 평가이며 최종 테스트가 아니다.
BOA 모델의 실제 경로만 새로 평가하며, 각 날짜의 경매 테이프 해시를 저장한다.
이전 저장 수치와 직접 비교하려면 같은 패키지 환경과 경매 테이프인지 먼저 확인해야 한다.
출력은 실제 BOA 경로의 일별 지표, 5분별 비중과 행동, 실행 설정 및 요약표이다.
소스 변경 없이 출력 경로를 달리해 실행한다.

```bash
python3 research_report/pacing_boa/code/run.py --days 1000 --out research_report/pacing_boa/results/run_001
```

필요 패키지: numpy, scipy, scikit-learn, joblib, threadpoolctl.
기존 학습 모델을 불러오는 환경을 사용한다. numba 및 최적화 패키지는 필요 없다.
