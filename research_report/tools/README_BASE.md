# 광고 예산 페이싱 연구: 실험 이력·고정 프로토콜 평가·재현 자료

> 제목의 연구 대상은 광고 예산 페이싱이다. 본 문서는 탐색 실패를 포함한 연구 이력을 보존한다. 최종 결과는 고정 가격 오프라인 재생의 서술적 비교이며, 통계적 유의성·실서비스 인과 효과·전체 시장 일반화를 입증한 논문 결과가 아니다. 원시 결과 파일이 본문보다 우선하며, 없는 기록은 추정해서 채우지 않는다.

## 1. 연구 질문과 현재 결론

하루 예산을 시간에 비례하여 집행할 때, 고정된 반응 계수의 제어기보다 관측 상태에 따라 계수를 선택하는 학습 정책이 추적 오차를 줄이면서 기대 전환을 보존할 수 있는가?

- 최종 v11의 사전 고정된 기간 24~27, 공개 벤치마크 광고주 48명에서 평균 TE가 18.96% 감소하고 평균 기대 전환이 4.56% 증가했다. 네 기간 각각의 광고주 평균도 두 지표가 함께 개선됐다.
- 그러나 광고주·기간별 192개 사례 중 TE 개선은 67개(34.9%), TE 개선과 기대 전환 98% 보존을 동시에 충족한 사례는 61개(31.8%)였다. 평균의 개선을 매 사례의 안정적 개선으로 해석하면 안 된다.
- 광고주별 네 기간 평균에서는 35/48명이 TE 개선과 기대 전환 98% 보존을 함께 충족했다. 나머지 13명의 평균 TE는 악화됐다. 광고주 평균과 사례별 빈도는 서로 다른 집계다.
- 선택 모델은 `forest_cost_0.1`이다. 동일 구조의 시간 전용 forest를 평가하지 않았으므로 선택 모델의 성과를 환경 피처의 순수 효과로 분리할 수 없다. 단일 정책 트리끼리의 비교에서도 환경 피처의 추가 효과는 일관되지 않았다.
- 따라서 현재 지지되는 것은 **이 벤치마크에서 선택된 학습 기반 계수 정책의 평균 개선**이다. **레짐 군집화의 효과, 모든 광고주에 대한 안전성, 실제 매출 개선**은 입증되지 않았다. 최종 모델에 HDBSCAN 군집이 직접 들어갔다고 서술하지 않는다.

## 2. 가설·평가 대상·판정 범위

| 질문 | 수행한 분석 | 현재 판정 |
|---|---|---|

## 4. v11 데이터와 분할

공식 공개 최종 데이터 묶음의 URL 형식:

`https://alimama-bidding-competition.oss-cn-beijing.aliyuncs.com/share/final/autoBidding_general_track_final_data_period_{pack}.zip`

| 구분 | periods | episodes (48광고주/기간) | 용도 |
|---|---|---:|---|
| 이전 개발 이력 | 7~15 | 버전별 상이 | v11 설계 참고. 새 테스트로 재사용하지 않음 |
| TRAIN | 16~21 | 288 | 초기화·상태 수집·비용 학습 |
| TUNE | 22~23 | 96 | 고정 기준 탐색, 모델·벌점·활성화 선택 |
| TEST | 24~27 | 192 | 설정 고정 뒤 전체 연속 재생 |

광고주를 무작위로 4명 뽑은 실험이 아니다. 공개 데이터에서 48명을 전수 확인한다. 실제 광고주 ID는 `advertisers.json`을 따른다. 공개 벤치마크의 전수가 현실 광고시장 전체의 대표 표본이라는 뜻은 아니다. 광고주를 분리한 cold-start 평가도 아니다.

원본 행을 무작위 분할하지 않고 기간을 통째로 분리했다. 같은 광고주를 미래 기간에서 평가하므로 알려진 광고주의 기간 변화에 대한 평가다. 기간 번호의 독립성·현실 날짜와의 대응을 확인하지 않고 4개의 독립 현업 날짜라고 단정하지 않는다.

입력은 period, advertiser, budget, CPAConstraint, timeStepIndex, pvIndex, pValue, pValueSigma, leastWinningCost이다. 원본 bid·실제 conversionAction을 그대로 모방하는 PI 학습이 아니다. 데이터 묶음별 원본 ZIP SHA256·행 수·URL은 pack manifest에 보존된다. 약4,800만 행/묶음이라는 행 수와 독립 학습 상태 수를 혼동하지 않는다.

## 5. 재생 환경과 제어기

하루는48틱이며 목표 누적 지출은 `B*(t+1)/48`이다. 제어 전 오차는 `t/48 - spent_before/B`, 제어 후 오차는 `(t+1)/48 - spent_after/B`다.

제어기는 로그 입찰 승수 `u`를 계산한다. `alpha=exp(u)`, `u_raw=bias+kp*error+ki*integral_candidate`. 적분 후보는 `integral+error/48`이다. 포화 방향으로 적분이 더 누적되는 경우 적분 갱신을 막는 clamp anti-windup을 적용한다. `u∈[-6,4]`, 한 틱 로그 출력 변화는 최대0.5이다. 초기 적분0, 초기 로그 출력bias이며 잔여 예산·적분·직전 출력은 계수 전환 때 유지된다.

기본 입찰액은 `CPAConstraint*pValue`, 낙찰 판단은 `alpha*base_bid >= leastWinningCost`, 비용은 고정된 leastWinningCost로 재생한다. 이는 경쟁자 반응이 없는 고정 가격 재생이며 자체 생성된 온라인 경매 시뮬레이터나 실제 first-price 전략 효과와 동일하지 않다.

기대 전환은 `E[clip(N(pValue,pValueSigma²),0,1)]`의 분석적 계산을 사용한다. pValueSigma를 정규분포의 scale로 해석하는 현재 구현을 기준으로 한다. 확률적 실제 구매건수·매출과 다르다. 틱 내부 예산 초과 시 seed42에서 period/ad/tick으로 파생한 공통 랜덤 우선순위로 소진을 처리한다. 모델별로 다른 난수를 줘 우열을 만들지 않는다. 반복 실행은 같은 난수·기대값 재생이므로 독립 환경 반복이 아니다.

잔여 예산0.1 미만이면 낙찰·학습 결정 대상에서 제외된다. 전체 에피소드는 최종 평가에 그대로 남긴다. 실제 전환 하한은 개별 행동마다 강제로 보장하지 않는다.

## 6. v11 학습 방식의 정확한 기술

### 6.1 초기화와 고정 비교군

광고주별 bias는 TRAIN의 각 에피소드 첫4틱에서 균등 지출 목표에 대응하는 입찰 문턱을 이용해 추정하고 중앙값을 취한다. 고정 기준의 후보는 kp={4,16,64}, ki={0,.3,3}의9쌍과 이전 개발에서 얻은 `(19.188179966639105,.06278467600183289)` 한 쌍, 총10쌍이다. 공통 offset={-.4,0,.4}를 더해 총30설정을 TUNE에서 평가한다.

기준 reference는 kp16,ki0,offset0이다. reference 평균 기대 전환98%를 보존하는 설정 중 J 최소를 고른다. 모든 학습 정책은 선택된 고정 기준과 동일한 bias·출력 제한을 쓴다. 이 고정 비교군은 유한 탐색의 최선이며 전역 최적 PI나 현업 최적 정책을 뜻하지 않는다.

TUNE에서 고른 고정 기준이 학습 라벨·roll-in 상태에도 사용된다. 따라서 TUNE은 학습 과정과 완전히 독립인 감사 집합이 아니라 파이프라인 전체의 개발·설정 선택 집합이다. TEST는 분리됐지만 TUNE 성능을 편향 없는 최종 성능으로 인용하지 않는다.

### 6.2 관측 정보

피처는23개다. `time_left, remaining_ratio, error, integral, log_alpha, last_spend_ratio, recent_spend_ratio, log_volume, volume_change, volume_cv, value_median, value_spread, price_value_median, price_value_q90, price_value_change, price_shift, value_shift, volume_shift, reference_capacity, spend_sensitivity, log_budget, log_cpa, bias`.

결정 시점 이전 틱의 관측과 제어 상태를 사용한다. 시장 피처는 과거 낙찰 실패 기회를 포함한 가격 정보가 플랫폼에서 보인다고 가정한다. 일반 광고주가 같은 정보를 얻을 수 있다고 가정하면 안 된다. 피처 이름만으로 단위를 임의 해석하지 말고 함께 보존한 feature/prepare_episode 소스를 확인한다. 광고주 정적 피처와 bias가 포함되어 있으므로 순수 시장 레짐 효과와도 구분한다.

### 6.3 상태 수집과 학습 표본

첫1틱은 기준 설정으로 관측하고 이후 결정 시점은1,7,13,19,25,31,37,43이다. 선택 계수는 최대6틱, 마지막은5틱 유지한다. 각 TRAIN 에피소드에서 이8시점 중3개를 seed20261105로 비복원 추출한다. 1차 최대864상태, 정책 유도 상태 추가 뒤 각 후보 최대1728행이며 예산 소진 등에 따라 실제 수는 줄 수 있다. 실제 수·coverage는 state_sampling.json 및 learning_audit.csv가 기준이다.

학습 가중치는 기간별 동일, 기간 내 `(광고주,prefix)` 그룹별 동일, 그룹 내 상태별 동일이다. 동일한 상태가 다른 prefix에서 반복될 수 있으므로 학습 행 수를 독립 표본 수로 보고하지 않는다. 평가에서는 샘플링 없이 모든 에피소드의 모든 유효 결정 시점을 사용한다.

### 6.4 비용 라벨과 정책 개선

상태s에서 후보 계수a를 최대6틱 적용하고, 그 뒤 continuation 정책으로 하루 끝까지 재생해 남은 구간의 비용과 기대 전환을 계산한다.

`J_tail(s,a)=sum_tail(abs(error))/48 + .01*sum_tail(du)/47`

`C(s,a)=J_tail(s,a)+lambda*max(0,.98*V_tail(s,base)-V_tail(s,a))/max(V_tail(s,base),1)`

상태마다 기준 행동의 C를 모든 후보에서 빼서 상대 비용으로 학습한다. argmin은 변하지 않는다. 여기서 V_tail의 base는 첫 구간만 기준 행동이고 그 뒤에는 같은 continuation이다. 항상 고정 정책을 하루 끝까지 실행한 가치라는 뜻은 아니다. 전환 벌점은 부드러운 벌점이며 위반을 불가능하게 하는 제약이 아니다.

0차는 고정 제어기 continuation으로 학습한다. 그 초기 정책을 TRAIN에서 실행해 새 상태를 수집하고, 기존 상태와 추가 상태 모두를 동일한 초기 학습 정책 continuation으로 다시 라벨링해 최종 모델을 학습한다. 학습 정책이 만드는 상태 분포와 후속 행동을 일부 반영하는 한 번의 근사 정책 개선이다. 반복 수렴·최적성·단조 개선은 보장하지 않는다.

목적함수의 주의점: 최종 J의 TV는 인접48틱 사이47개 차이의 평균인 반면, Q 라벨은 분기 시작 경계의 변화까지 `du`에 포함한다. 첫 분기t=1은 최종 첫 인접 변화와 대응하지만 일반적으로 tail objective의 경계 처리임을 명시한다. 국소 라벨을 독립 전체 에피소드 점수와 동일하다고 쓰지 않는다.

### 6.5 모델과 선택

| family | 구현 | 선택 후보 |
|---|---|---|
| policy_tree | 깊이2 탐욕적 직접 비용 정책 트리, 내부20행 이상일 때 분기, 자식 최소10행, 피처별20/40/60/80분위 문턱 | lambda .1,1 |
| forest_cost | ExtraTreesRegressor64개, max_depth5, min_samples_leaf5, random_state42, fit n_jobs2 | lambda .1,1 |
| time_only | 위 policy_tree와 같은 학습 방식, time_left만 입력 | lambda .1,1 |

forest는 상대 행동 비용 벡터를 회귀로 예측한 뒤 최소 예측 비용 행동을 고른다. 이를 forest 자체가 직접 정책 regret를 최적화한다고 표현하지 않는다. 직접 비용 분기는 policy_tree에 해당한다. 동일 비용이면 기준 행동을 우선한다.

모델 선택은 기준 평균 기대 전환98% 미달량을 먼저 최소화하고 그 뒤 J를 최소화하는 사전 정한 순서다. 전부 미달해도 원시 후보는 저장한다. 채택(enabled)은 TUNE에서 value≥98% fixed, TE≤98% fixed, J<fixed를 모두 충족해야 한다. 실패하면 selected_policy는 fixed로 복귀하되 learned_raw는 별도로 보고한다.

실제 선택: forest_cost_0.1, enabled=true. 검증 TE .05860447108707943, J .06156896125407487, value31.292085977267384. 고정 기준 base index6, offset-.4; 실제 kp/ki는 fixed_baseline.json의 pool[6]에서 확인한다(현재 코드 정렬 기준 kp19.188179966639105,ki.06278467600183289). 검증 fixed TE .08011831289215578, J .08323376868869732, value29.541637588698315.

코드는 FROZEN_BEFORE_TEST.json을 저장한 다음에 TEST 데이터 다운로드·평가를 시작하도록 되어 있다. 외부 사전등록 저장소의 타임스탬프 증명이 아니라 로컬 프로토콜·실행 순서 기록이다.

## 7. 평가 지표·집계·통계적 해석

- `TE=mean_t(abs((t+1)/48 - cumulative_spend_t/B))`: 예산으로 정규화한 누적 지출 추적 오차. 작을수록 좋다. .069304→.056163은 상대18.96% 감소이자 정규화 오차0.013141(예산 대비1.3141%p) 감소다. 광고비 자체가18.96% 절감됐다는 뜻이 아니다.
- `value=sum(expected_clipped_conversion)`: 기대 전환. 클수록 좋으며 매출·실제 구매건수와 다르다.
- `TV=mean(abs(diff(log(alpha))))`: 입찰 승수의 로그 변화량. 비용 변동이나 매출 변동의 표준편차가 아니다.
- `J=TE+.01*TV`: 사전 정의된 종합 비용. J 감소와 TE 감소는 수치가 다르다.
- `unspent=last_remaining/B`: 미사용 예산 비율. .009128→.011347은0.2219%p 증가.
- `changed_ticks`: 고정 기준과 다른 **계수 후보**를 사용한 틱 수. 계수 변경 이벤트 수나 입찰액이 달라진 경매 수가 아니다.
- macro 집계는 기간 내 광고주 평균 후 기간 평균이다. 모든 기간에 광고주48명이 있어 전체192사례 평균과 같다. 지출 규모 가중·전체 전환 합산 지표와 다르다.
- 개선율은 `100*(mean_fixed-mean_learned)/mean_fixed`, 전환 변화율은 `100*(mean_learned-mean_fixed)/mean_fixed`. 개별 비율의 평균과 혼동하지 않는다. 기준값0인 개별 비율은 미정의로 둔다.

기간 내 광고주들은 시장을 공유하고 같은 광고주는 기간에 걸쳐 반복된다. 192개 사례를 독립 시장으로 간주하는 t검정이나 겹친 창 bootstrap을 하지 않는다. 최종 기간도4개뿐이며 독립 생성 여부를 강하게 보장하지 못한다. p-value·신뢰구간 없이 기간별 효과·광고주별 분포·꼬리 위험을 서술한다. 효과 크기의 실무적 의미와 통계적 유의성은 다르다.

## 9. 방법론 감사: 해결된 부분과 미해결 부분

1. 이전4광고주 선택은 무작위 표본이 아니었다. v11은48명 전수지만 현실 대표성·신규 광고주 일반화는 여전히 미검증이다.
2. v9의 다중 출력 MSE·임의20배 scaling·전환 clipping과 예측 행동 gate가 좋은 행동 선택을 보장하지 않았다. v11은 행동별 후속 비용 라벨을 사용하지만 forest의 회귀 오차와 실제 결정 품질 차이는 남는다.
3. v10의 고정 continuation 불일치는 v11에서 기존/추가 상태 모두 현재 초기 정책 continuation으로 다시 라벨링하여 줄였다. 최종 갱신 정책과 continuation은 동일하지 않으므로 완전한 일치·수렴을 주장하지 않는다.
4. 초기6틱 무행동을1틱으로 줄였지만, 미래 정보 없이 첫틱 이전 시장 대응은 하지 않는다. 이를 단독 변경한 인과 절제는 없다.
5. 고정 기준을 충분히 탐색했으나 후보공간10쌍·offset3개로 제한된다. 더 강한 MPC/적응형 제어기·같은 구조 time-only forest와의 우열은 미검증이다.
6. 안전성은 평균 전환 벌점과 검증 gate 수준이다. 개별 광고주·기간 전환 하한, 손실 상한, 실시간 복귀가 보장되지 않는다.
7. 고정 가격·과거 전체 시장 관측·고정 순서 난수 등의 모델 가정이 현실 광고시장과 다르다. 오프폴리시 추정기의 무편향성이나 온라인 실험의 인과 효과를 주장하지 않는다.
8. 개발 과정에서 여러 모델/실험을 시도했고 실패 후 설계를 바꿨다. v11은 이전7~15를 개발로 처리하고 새24~27을 마지막에 평가했지만, 연구 전체가 단일 최초 가설 검정이었다고 쓰지 않는다.
9. 실행시간은 수렴·과소학습의 검정 기준이 아니다. 실제 상태 수·모델 구조·훈련 비용/결정 regret는 원시 감사 파일로 확인한다. ExtraTrees는 신경망 epoch 학습과 다른 알고리즘이다.
10. v11에는 최종 평가의 틱별 전체 trace를 저장하는 코드가 없다. final_episodes.csv는 에피소드 지표다. 저장되지 않은 변화 시점/충격 후 회복시간을 관측한 것처럼 복원하지 않는다.
11. v11 첫 프로토콜 생성 시 소스 hash 기록과 합성 smoke test는 있었다. 전체 실제 데이터에 대한 사전 무오류 보증·공식 논문 완전 재현 검증은 아니다. 재시도·에러 로그를 삭제하지 않는다.

## 10. 보고서·논문 작성에 사용할 주장

사용 가능한 서술:

> 공개 벤치마크의 광고주48명과 설정 고정 후 평가한4기간에서, 비용 예측 기반 계수 선택 정책은 유한 탐색으로 선정한 고정 제어기보다 macro 평균 추적 오차를18.96% 낮추고 기대 전환을4.56% 높였다. 기간별 평균에서도 같은 개선 방향을 보였다. 다만192개 광고주·기간 사례 중 추적 오차 개선은34.9%였고 큰 악화 사례가 있어, 평균 개선과 개별 운용 안정성을 구분해야 한다.

사용 불가: '유의하게 개선', '실제 매출 증가', '모든 광고주 안전', '레짐 인식의 인과 효과 입증', '최적 PI보다 우수', '온라인 RL 학습 성공', '독립192회 실험', '원 논문 재현 성공', '24~27에 맞춘 추가 변경 뒤에도 새 테스트'.

보고서 권장 구성: 문제와 적용 조건 → 이전 탐색과 실패 → 고정 프로토콜/데이터 → 재생/모델/목적함수 → 전체·기간별 결과 → 광고주별 이질성 및 최악 사례 → 통제 비교의 한계 → 재현성과 남은 문제. 평균 TE만을 강조하는 결론은 피한다.

향후 과제(미수행): 같은 forest의 시간 전용/전체 피처 비교, 손실 위험 분석을 반영한 새로운 안전 정책, 추가 새 기간이나 실제 운용 평가. 현재 최종 결과를 보고 생긴 사후 아이디어이며 현 테스트를 재사용한 확증 결과로 쓰지 않는다.

## 11. 재현·원시 자료의 구조

이 README의 아래 자동 생성 부록은 사용자 컴퓨터의 실제 완료 결과를 읽어 만든다. 원본 실험을 변경하거나 재학습하지 않는다.

- `research_report/results/`: auctionnet_lab/runs, pacing_v11/auctionnet_lab/runs, auctionnet_paper_v7/outputs 및 존재하는 레거시 outputs/experiments를 수집한다. 과거 실행과 v11의 CSV·JSON·로그·규칙·모델. 원 경로를 유지하며 각 파일 SHA256을 기록한다.
- `research_report/derived/`: 원시 에피소드 표에서 다시 계산한 대응 비교·광고주별 평균·전체요약·기간별요약·빈도·꼬리 위험.
- `research_report/training_labels/`: 현재 v11 Q 캐시의 상태·23피처·후속 비용·기대 전환을 JSONL gzip으로 추출. 파일 수/행 수/누락 여부를 감사 기록으로 남긴다. 중간 모델 전체가 저장되지 않은 경우 초기 정책 단계의 정확한 재현에는 재학습이 필요하다.
- `research_report/source/`: 프로젝트 실행 소스, 의존성 명세 및 보존한 감사 문서. 실험 직후 확인한 현재 바이트이며 최초 실행 당시와 동일한지는 PROTOCOL hash 검사를 따른다.
- `research_report/data_inventory.csv`: 원시 Parquet의 경로·크기·행 수·스키마. 다중GB 원본 경매 행은 Git에 올리지 않으며 원본 URL·pack SHA로 재취득한다. 이것은 원시 결과표를 모두 보존하는 것과 구분한다.
- `research_report/file_manifest.csv`: 포함 파일 원 경로·보존 경로·크기·SHA256. 40MiB 초과 파일은 gzip 후 분할하고 복원 정보도 기록한다.
- `research_report/results/pacing_report_tools/historical_reference/`: 이전에 제공된 컨텍스트 아카이브에서 실제 읽은 v3·v4·v5 결과. 현재 로컬 원본과 별도 출처로 보존한다.
- `research_report/evidence/user_console.md`: 사용자가 전달한 콘솔 원문. 반올림 요약과 파일 실측 결과를 구분한다.
- `research_report/audit.json`: 필수 결과 검증, 소스 hash, 누락/자료 제외, 환경 및 Git 기준 커밋. 환경 기록 시점은 보고서 생성 시점이지 실험 당시 환경 lock 증명이 아니다.

v11 필수 원시 파일: PROTOCOL.json, FROZEN_BEFORE_TEST.json, advertisers.json, fixed_baseline.json, fixed_baseline_search.csv, state_sampling.json, learning_audit.csv, policy_selection.csv, final_episodes.csv, final_summary.csv, final_by_period.csv, paired_final.csv, DONE.json. 파일명은 대소문자를 구분한다. JSON 규칙은 `*_rules.json`에 있으며 txt 검색에서 안 나온 것이 규칙 자체가 없다는 뜻은 아니다. forest는 단일 짧은 규칙표가 아니며 저장된 joblib로 복원한다. 신뢰할 수 있는 본인 실험 joblib만 로드한다.

재현 명령은 별도 빈 디렉터리/복사본에서 보존된 소스로 실행한다. 원본 완료 디렉터리에서 무조건 재실행하거나 test를 보고 정책을 고르지 않는다. Python/NumPy/scikit-learn·코드·원본 데이터의 버전 일치가 필요하며 bitwise 일치 여부는 별도로 검증한다.
