# 광고 예산 페이싱 A 기준 모델 / ABC 공통 프로토콜

이 폴더는 레짐 분류와 강화학습을 사용하지 않는다. A(고정 PI)를 구현하며,
B(선형 회귀 예측+PI)와 C(신경망 예측+PI)가 연결할 인터페이스를 제공한다.
B/C 예측 모델 자체는 아직 구현하지 않았다.

## 실험 질문과 비교 효과

최종 승수 = 기본 승수 + PI 보정. 마지막에 공통 [0,1] 제한을 적용한다.

| 모델 | 기본 승수 | 공통 부분 |
|---|---|---|
| A | 사전 고정값 0.5 | 위치형 PI, anti-windup, 예산 검사 |
| B | 선형 회귀로 예상 지출을 구해 후보 선택 | A와 동일 |
| C | 신경망으로 예상 지출을 구해 후보 선택 | A와 동일 |

A는 허용된 시장 이력에 접근할 수 있지만 기본 정책 정의상 오차만 이용한다.
B/C가 이력을 이용하는 것은 연구에서 추가하는 처리이며, 정보 접근 시점은 같다.

두 가지 분석을 구분한다.

1. **주 분석: 모듈 추가 효과.** 검증으로 선택한 A의 Kp/Ki를 B/C에도 그대로
   고정한다. B-A는 선형 예측 사전 조정 추가 효과, C-B는 공통 학습 조건 아래
   예측기를 신경망으로 교체한 효과다. B/C에서의 독립 PI 재튜닝이 없어
   제어 보정 차이와 섞이지 않는다. A에 최적화된 계수가 B/C에는 불리할 수
   있으므로 이 분석으로 각 방식의 최선 성능까지 주장하지 않는다.
2. **보조 분석: 방식별 최종 성능.** A/B/C에 같은 검증 환경과 동일한 최대
   종단간 설정 평가 횟수(기본 40회)를 주고 PI/모델 설정을 각각 선택한다.
   이 결과는 방식 전체 비교이며 예측기 단독 효과라고 해석하지 않는다.
   모델 학습 횟수, 시간, 파라미터 수도 별도로 기록한다.

예측 성능은 공통 보류 데이터에서 B/C를 비교하고 실제 추종 성능도 함께 본다.
정확한 예측이 좋은 제어를 보장하지 않으며, 긍정적인 결과를 전제로 하지 않는다.

## 통제변인

| 항목 | 고정 규칙 |
|---|---|
| 경매 | 한 대상 광고주, 외생 경쟁 최고 입찰, first-price; 동률은 대상 광고주 패배 |
| 결제 | 낙찰 시 자신의 입찰가 결제. 경쟁 가격을 지출로 사용하지 않음 |
| 기준 입찰 | 환경이 생성한 기회별 값; 모든 모델에 동일. 승수로만 조절 |
| 목표 | 24시간 선형 누적 지출; 중간에 잔여 예산 기준 목표 재설정 금지 |
| 행동 | 연속 승수 [0,1]; 같은 PI와 clip 구현, rate limit/필터 추가 없음 |
| 갱신 | 기본 5분 간격, 288틱; 구간 내 승수 고정 |
| 정보 시점 | t구간 행동은 t-1구간까지의 정보만 사용. t구간 경매 수·경쟁 가격 제공 금지 |
| 초기화 | 모든 모델 첫 승수 0.5, 적분 0, 없는 이력은 유효성 마스크 0 |
| 예산 | 경매 순서대로 처리; 잔여 예산보다 비싼 입찰은 건너뜀. 입찰가를 잔여 예산으로 잘라 낙찰시키지 않음 |
| 외부 환경 | 하루 전체의 경매 수·기준 입찰·경쟁 입찰을 행동 전에 생성해 재사용 |
| 예측 입력 | 후보 승수, 시간, log 예산, 지출 비율, 오차 + 최근 12틱 이력; B/C 완전 동일 |
| 이력 | 유효성, 승수, 지출/예산, log(1+기회 수), 낙찰률, 기준 입찰 평균, 예산 검열 여부 |
| 후보 선택 | B/C 모두 101개 기본 승수 후보. 예상 지출과 B/T 차이가 최소인 후보, 동률이면 낮은 승수 |
| 최종 행동 | 후보는 기본 승수에만 적용. PI 보정 후에는 A/B/C 모두 연속값 |
| 모델 학습 | B/C 같은 버퍼·행 필터·fit/내부검증 분할·스케일링. 온라인 재학습 없음 |
| 스케일러 | fit 데이터만으로 적합; 검증/테스트를 섞지 않음 |
| 예측 라벨 | 실제 다음 구간 지출/예산. 예산 제한 결과도 동일하게 포함하고 실제 결제 지출을 예측 |
| 내부검증 | 학습용 하루 중 앞 75% fit, 뒤 25% 내부검증. B/C 같은 분할. C의 조기종료도 여기서만 수행 |
| 하이퍼파라미터 | 주 분석에서는 B/C 예측기 설정을 학습 내부검증으로 선택. 외부검증 반복 조회로 모델 탐색 금지 |
| 외부검증 | A PI 선택에 사용. 보조 분석은 모델별 같은 종단간 평가 횟수 적용 |
| 평가 | 하루 단위 평균, 모델 간 대응 차이의 하루 bootstrap; 시간창을 독립 표본으로 세지 않음 |

B/C 예측 모델의 구조·정규화 강도·학습 epoch 상한·조기종료 규칙과 탐색 횟수는
구현 시 테스트 결과를 보기 전에 추가 동결한다. 이 버전은 그 설정을 대신 정하거나
B/C까지 완료됐다고 주장하지 않는다. 최종 ABC 평가 전 세 모델의 artifact hash를
함께 기록해야 한다. A 테스트 결과를 본 뒤 BC 설계를 바꾸면 기존 test는 개발자료가
되므로 새로운 미공개 최종 평가 환경을 확보해야 한다.

## PI 수식과 시간 순서

구간 t 시작 전 e=t/T-S/B, I*=I+e/T로 계산한다.
raw=base+Kp*e+Ki*I*를 구한다. 상한에서 더 올리는 오차 또는 하한에서 더
낮추는 오차면 이번 적분을 거부하고 기존 I로 raw를 재계산한다.
최종 승수를 clip한 뒤 t구간의 경매에 적용한다. 결제 후 이력을 갱신한다.
이 위치형 출력값을 이전 승수에 다시 더하지 않는다.

주 지표는 mean_t |(t+1)/T-S_(t+1)/B|.
튜닝 목적은 하루별 (추종 오차+최종 미소진율)의 평균이다. 가중치 1은 사전
선택한 실험 설계이며 논문에서 보장한 값이 아니다. 승수 변동, 최대 선행 지출,
포화 비율을 별도로 보고한다. 승수 변동을 줄인 것만으로 개선이라고 하지 않는다.

## 무작위 환경과 해석 범위

`generate()`는 하루별로 트래픽 평균·일중 위상/진폭·경쟁 수준·예산 비율·충격
시점/기간/강도를 뽑는다. 트래픽은 Poisson, 기준/경쟁 입찰은 lognormal이며,
완만한 일중 변화, 상관 잡음과 선택적 충격이 있다. 시간마다 시장을 완전히
독립적으로 다시 뽑지 않는다. 예산은 생성 전 분포 파라미터로 정하고 미래
실현 지출량에 맞춰 설정하지 않는다.

**이 분포·범위는 실제 데이터로 교정하지 않은 공학 검증용 설정이다.**
기존 Yahoo 시뮬레이터나 AuctionNet 원본을 재현한 것이 아니다. 기존 최근
AuctionNet 코드는 fixed-price replay이고 본 코드는 first-price이므로 결과를
동일 조건으로 섞지 않는다. 실제 도메인 결론 전에는 데이터 기반 범위 교정과
해당 데이터 출처를 명시하고 새 프로토콜로 다시 동결해야 한다.

`capacity_shortfall`은 최대 입찰에서의 예산 무제한 prefix 지출량조차 목표에
미달하는지를 보는 필요조건 검사다. 0이라고 추종 가능성을 보장하지 않는다.
모든 날을 주 결과에 포함하고 이 진단을 따로 보고한다. 유리한 날만 사후 선별하지 않는다.

기본 split은 서로 다른 40일(train), 20일(validation), 60일(test)이다.
이는 예시 계산 예산이며 표본 수의 충분성을 보장하지 않는다. 동일한 생성분포의
새 하루를 평가하며, 분포 밖 일반화/OOD 성능은 아직 평가하지 않는다.

## 실행

Python 3.10 이상, NumPy 필요. 저장소 루트에서 실행한다.

```bash
python3 -m pip install 'numpy>=1.24,<3'
python3 -m unittest discover -s experiments/pacing_abc -p 'test_*.py' -v

python3 experiments/pacing_abc/run.py init --out outputs/pacing_abc_v1
python3 experiments/pacing_abc/run.py collect --out outputs/pacing_abc_v1
python3 experiments/pacing_abc/run.py tune --out outputs/pacing_abc_v1
```

- init: 소스/NumPy 버전·환경·split·선택 기준 기록. 테스트 데이터 생성 안 함.
- collect: B/C용 학습 버퍼. 하루 내 무작위 행동을 실제로 적용한 라벨만 저장.
- tune: 고정 후보 40개를 같은 검증 20일로 비교한 뒤 A 동결. 테스트 생성 안 함.
- B/C 구현·설정 동결 전에는 아래 최종 평가를 실행하지 않는 것을 권장한다.

```bash
python3 experiments/pacing_abc/run.py evaluate --out outputs/pacing_abc_v1
```

테스트 접근 기록을 먼저 만들고 날짜별 결과를 저장한다. 중단 후 같은 설정으로
재개할 수 있고, 완료 후 재호출은 저장된 결과만 출력한다. A 설정이 바뀌면
기존 테스트 결과에 이어 쓰지 않는다. 파일 삭제까지 막는 보안 장치는 아니므로
실험자가 테스트를 열고 튜닝하지 않는 절차도 지켜야 한다.

A 탐색 후보에는 무보정(Kp=Ki=0)과 P(Kp=4, Ki=0)를 포함한다. 나머지는
Kp=0.1~100, Ki=0.01~100의 로그 범위에서 사전 seed로 뽑으며 일부는 Ki=0이다.
이는 제한된 탐색 범위에서의 선택이고 전역 최적 PI를 보장하지 않는다. 상한 근처
설정이 선택되거나 목적함수 간 상충이 크면 최종 평가 전에 개발 환경에서 범위와
튜닝 예산을 재검토하고 새 프로토콜을 동결한다. 사후 테스트 조정은 하지 않는다.

작은 연결 점검은 다른 출력 경로와 별도 config로 실행한다. 작은 실험을 정식
성능 근거로 쓰지 않는다. `init --config some_config.json`으로 Config 필드를
일부 재정의할 수 있다. 한 번 init한 실행의 설정/소스를 변경하면 거부한다.

## 코드와 결과

- core.py: 환경 생성, 불변 경매 tape, 관측, PI, B/C 어댑터, 예산 처리, 지표.
- run.py: 프로토콜, 학습 버퍼, 튜닝, 동결, A 평가, 실행 잠금.
- test_core.py: 결제, 예산, 인과성, 결정성, anti-windup, 전체 경로 검사.
- protocol.json: 실험 규칙과 split. frozen_A.json: 선택 계수 및 검증 tape hash.
- train_prediction.csv: B/C 공통 학습 데이터. x열만 입력이며 순서는 core.features 참고. 현재 행의 budget_censored는 라벨 메타데이터로 입력 금지.
- test_A/episodes.csv, trace_*.csv, summary.json: 일별 지표·구간 로그·요약.

환경의 실제 경매·경쟁 가격은 정책 입력으로 전달하지 않는다. 기존 실험·모델·
클러스터링 문서를 수정하지 않는다. 기본 실행은 다운로드·외부 서비스 없이 동작한다.
